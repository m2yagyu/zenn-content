前章で作った画像は、裏側で「ノイズを少しずつ取り除く」という処理を経て出てきています。この言い方は、インクが水の中に広がっていく現象の説明とほとんど同じに聞こえます。

実際、同じです。この章では2次元のトイデータで拡散モデルをゼロから実装し、forward processが拡散方程式、reverse processがランジュバン方程式の時間反転であることを確かめます。

3章で温度 $\mathcal{T}$ が出てきたことを覚えておいてください。拡散モデルのノイズスケジュール $\beta_t$ は、実は温度のスケジュールです。

この記事を読むと、画像生成AIの裏側で動く「拡散モデル」の仕組みを、自分の手で小さなモデルを学習させながら理解できます。数式は後半にまとめてあるので、コードだけ動かして雰囲気をつかむだけでもOKです。

[前回の記事](https://zenn.dev/m2yagyu/articles/text-to-image-huggingface-colab)で、文章から画像を作るときに裏側で「ノイズを少しずつ取り除く」仕組みが動いていることに触れました。今回はその中身を、実際に動くコードと、物理の「拡散」という視点から覗いてみます。

## さっさと動かしてみよう

今回はHugging Faceなどの外部APIを使わず、[Google Colab](https://colab.research.google.com/)の中だけで完結する小さな拡散モデルを、その場で学習させます。使うデータは画像ではなく、2次元平面上の「二つの月（two moons）」という形の点の集まりです。画像だと仕組みが分かりにくいですが、2次元の点なら「ノイズだった点々が、ちゃんと元の形に戻る」様子がそのまま目で見えます。

Colabで新しいノートブックを開き、次のセルを順番に実行してください（GPUは不要です）。

### セル1：元データを作る

```python
import numpy as np
import torch
import torch.nn as nn
import matplotlib.pyplot as plt
from sklearn.datasets import make_moons

torch.manual_seed(0)
np.random.seed(0)

X0, _ = make_moons(n_samples=2000, noise=0.05)
X0 = X0.astype(np.float32)
# 平均0・標準偏差1に揃える（forward processが分散1のガウス分布に向かう設計に合わせるため）
X0 = (X0 - X0.mean(0)) / X0.std(0)
X0 = torch.from_numpy(X0)

plt.figure(figsize=(4, 4))
plt.scatter(X0[:, 0], X0[:, 1], s=4)
plt.gca().set_aspect("equal")
plt.title("training data (two moons)")
plt.show()
```

これから「この形」をノイズから作れるようにモデルを学習させます。

### セル2：forward process（データにノイズを混ぜていく）

```python
T = 1000
betas = torch.linspace(1e-4, 0.02, T)       # 各ステップで混ぜるノイズの強さ beta_t
alphas = 1.0 - betas                        # alpha_t = 1 - beta_t
alpha_bars = torch.cumprod(alphas, dim=0)   # alpha_bar_t = alpha_1 * ... * alpha_t（数式の総乗Π）

def forward_sample(x0, t):
    """x0にステップtまでノイズを混ぜたx_tを返す"""
    a_bar = alpha_bars[t].unsqueeze(-1)
    eps = torch.randn_like(x0)
    # 元データを sqrt(a_bar) 倍に弱め、その分だけノイズを混ぜる（分散は常に1に保たれる）
    x_t = torch.sqrt(a_bar) * x0 + torch.sqrt(1 - a_bar) * eps
    return x_t, eps                         # 問題(x_t)と正解(eps)を同時に返すのが要点

# 最終ステップで元データの成分がどれだけ残っているかを確認する
print("alpha_bar[T-1]      =", alpha_bars[-1].item())
print("sqrt(alpha_bar[T-1]) =", alpha_bars[-1].sqrt().item())
```

```
alpha_bar[T-1]      = 4.035830352222547e-05
sqrt(alpha_bar[T-1]) = 0.006352818571031094
```

この`print`は地味ですが重要です。`x_t`の中の元データの成分は$\sqrt{\bar\alpha_t}$倍されて入ってくるので、最終ステップでこれが`0.006`まで小さくなっている、つまり「元の形の情報はほぼ完全に消えて、ただのガウスノイズになった」ことを意味します。後半で説明するように、拡散モデルは「最終状態が完全なガウスノイズである」ことを前提に逆再生を組み立てるので、ここが十分に0に近いことは設計上の必須条件です。

ステップ数`T`とノイズの強さ`betas`は、セットで決める必要があります。たとえば`betas`をこのままにして`T=100`に減らすと、$\bar\alpha_{T-1}$は`0.36`程度にしかならず、最後まで元の形がうっすら残ったままになります。この状態で逆再生を学習させると、後で出てくる図の下段はぼんやりした塊になってしまい、うまく復元できません。

### セル3：ノイズを予測する小さなモデル

```python
class NoisePredictor(nn.Module):
    def __init__(self, hidden=128):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(3, hidden), nn.SiLU(),   # 入力は (x, y, t) の3次元
            nn.Linear(hidden, hidden), nn.SiLU(),
            nn.Linear(hidden, 2),              # 出力は予測したノイズ (2次元)
        )

    def forward(self, x, t):
        t_norm = (t.float() / T).unsqueeze(-1)  # tを0〜1に正規化して入力に混ぜる
        inp = torch.cat([x, t_norm], dim=-1)
        return self.net(inp)

model = NoisePredictor()
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
```

### セル4：学習する

```python
n_steps = 20000
batch_size = 256
losses = []
for step in range(n_steps):
    idx = torch.randint(0, X0.shape[0], (batch_size,))
    x0 = X0[idx]
    t = torch.randint(0, T, (batch_size,))  # サンプルごとにバラバラなステップを引く（ここが核心）
    x_t, eps = forward_sample(x0, t)      # ノイズを混ぜて、混ぜた正解ノイズepsも受け取る
    eps_pred = model(x_t, t)              # モデルにノイズを当てさせる
    loss = ((eps_pred - eps) ** 2).mean() # 正解ノイズとの二乗誤差

    opt.zero_grad()
    loss.backward()
    opt.step()
    losses.append(loss.item())

    if (step + 1) % 5000 == 0:
        print(f"step {step+1}: loss = {np.mean(losses[-500:]):.4f}")

print("最終的な誤差:", np.mean(losses[-500:]))
```

```
step 5000: loss = 0.2497
step 10000: loss = 0.2460
step 15000: loss = 0.2355
step 20000: loss = 0.2321
最終的な誤差: 0.23213687726855278
```

GPUなしのCPUだけで完了します（筆者の環境では約10秒でした）。

誤差が`0.23`あたりで止まって0まで下がらないのは、学習に失敗しているからではありません。ノイズが強く混ざった状態の`x_t`を見せられても、「混ざっていたノイズがどれだったか」は原理的に完全には特定できないからです。モデルにできるのは平均的に一番ありそうなノイズを答えることまでで、その意味でこの値は下限に近いところにいます。

### セル5：reverse process（ノイズからデータを作る）

```python
@torch.no_grad()
def sample(n_samples=1000, record_steps=()):
    x = torch.randn(n_samples, 2)  # 完全なノイズからスタート
    frames = {}
    for t in reversed(range(T)):   # t = T-1, ..., 1, 0 と時間を遡る
        t_batch = torch.full((n_samples,), t, dtype=torch.long)
        eps_theta = model(x, t_batch)
        alpha_t, alpha_bar_t, beta_t = alphas[t], alpha_bars[t], betas[t]

        # 予測したノイズを取り除いた「1ステップ前の平均」
        mean = (1 / torch.sqrt(alpha_t)) * (
            x - (beta_t / torch.sqrt(1 - alpha_bar_t)) * eps_theta
        )
        if t > 0:
            sigma_t = torch.sqrt(beta_t)          # 揺らぎを少しだけ足し戻す
            x = mean + sigma_t * torch.randn_like(x)
        else:
            x = mean                              # 最後のステップは揺らぎを足さない

        if t in record_steps:
            frames[t] = x.clone()  # cloneを忘れると、後の更新で保存済みの値も書き換わる
    return frames

show_t = [0, 100, 400, 700, 999]
frames = sample(n_samples=1000, record_steps=set(show_t))
```

### セル6：forwardとreverseを並べて可視化する

```python
fwd_frames = {}
for t in show_t:
    t_batch = torch.full((1000,), t, dtype=torch.long)
    x_t, _ = forward_sample(X0[:1000], t_batch)
    fwd_frames[t] = x_t

fig, axes = plt.subplots(2, 5, figsize=(15, 6.4))
for i, t in enumerate(show_t):                      # 上段：データ → ノイズ
    pts = fwd_frames[t].numpy()

    axes[0, i].set_title(f"t = {t}", fontsize=11)

for i, t in enumerate(reversed(show_t)):            # 下段：ノイズ → データ

    axes[1, i].set_title(f"t = {t}", fontsize=11)

axes[0, 0].set_ylabel("forward\n(data -> noise)", fontsize=11)
axes[1, 0].set_ylabel("reverse\n(noise -> data)", fontsize=11)
for ax in axes.ravel():
    ax.set_xlim(-3.2, 3.2)   # 全パネルで同じ表示範囲に揃える
    ax.set_ylim(-3.2, 3.2)

    ax.set_xticks([])
    ax.set_yticks([])
```

![forward processでデータが徐々にノイズになり、reverse processでノイズから月型が復元される様子](/images/diffusion-toy-forward-reverse.png)

上段（forward）は、最初きれいな「二つの月」だった点が、ステップを重ねるごとにただのランダムな点の塊になっていく様子です。下段（reverse）は、その逆再生を学習済みモデルにやらせた結果で、完全なノイズ（t=999）から出発して、最終的に「二つの月」（t=0）が復元されています。誰も「月の形はこうだ」と教えていないのに、ノイズを予測するモデル1つだけでこの復元ができている、というのが拡散モデルの面白さです。

面白いのは、下段の形が現れるタイミングです。t=999から400あたりまではほとんどノイズのままで、t=100でようやく気配が出てきて、最後の100ステップで急に月型が決まります。序盤はノイズが支配的で「どちらに動けばデータらしくなるか」という手がかりがほとんどなく（この段階の分布はほぼ等方的なガウス分布なので、原点に向かって縮む力しか働きません）、データに近づくにつれて形の情報を持つ成分が強くなってくる、という事情を反映しています。

### セル7：復元できたかを数値で確かめる

見た目の印象だけでなく、数値でも確かめておきます。生成した各点について「元データの中で最も近い点までの距離」を測り、元データ同士で同じ量を測ったものと比べます。

```python
gen = frames[0]
d_gen = torch.cdist(gen, X0).min(dim=1).values
real = X0[torch.randperm(X0.shape[0])[:1000]]
d_real = torch.cdist(real, X0).kthvalue(2, dim=1).values  # 自分自身は除くので2番目
print(f"生成した点  → 元データへの距離: {d_gen.mean():.3f}")
print(f"元データ同士 → 元データへの距離: {d_real.mean():.3f}")
```

```
生成した点  → 元データへの距離: 0.047
元データ同士 → 元データへの距離: 0.020
```

元データ同士の間隔が`0.020`、生成した点から元データまでが`0.047`です。同じオーダーに収まっているので、生成された点は「月の形の上に乗っている」と言えます。まだ2倍ほど差があるのは、この小さなモデルの精度の限界です（`n_steps`を増やしたり`hidden`を大きくすると縮まります）。逆にもし復元に失敗していると、この値は`0.1`以上に大きく開きます。数値で見ておくと、図の見た目だけで判断せずに済みます。

## コードを読んでみよう

7つのセルを順に読んでいきますが、全部の行を同じ重さで説明すると、かえって「どこが拡散モデルの本質なのか」が埋もれてしまいます。そこで各セルについて、

- **本文には、「なぜそう書くのか」が拡散モデルの理屈に直結する行だけ**を置く
- Pythonの記法や、知らないと引っかかる落とし穴は、**折りたたみ**に分けて入れる

という形にしました。折りたたみは開かなくても本筋は追えます。逆に「そもそもこの記号が読めない」という場合は、そちらを開いてください。

先に要点だけ挙げておきます。この6つが分かれば、このコードは読めたことになります。

| # | 押さえる要点 | どこ |
| --- | --- | --- |
| 1 | データの散らばりを1に揃えるのは、理論の要求 | セル1 |
| 2 | `cumprod`が数式の総乗$\prod$そのもの | セル2 |
| 3 | 問題と正解を同時に作るので、教師データが要らない | セル2 |
| 4 | 入口が3・出口が2という形が、モデルの仕事の定義 | セル3 |

### セル1：元データを作る

**要点：`X0.std(0)`で割っている1行が、後半の理論と直結しています。**

```python
# 平均0・標準偏差1に揃える（forward processが分散1のガウス分布に向かう設計に合わせるため）
X0 = (X0 - X0.mean(0)) / X0.std(0)
```

forward processは「最終的に分散1の標準正規分布に行き着く」ように作られています。出発点のデータの分散も1に揃えておかないと、途中のステップで分散が1に保たれず、後半で説明する理論とコードが対応しなくなります。データを整える前処理というより、**理論の前提条件をコードで満たしている行**だと考えてください。

:::details Python / PyTorchの記法メモ（セル1）
- `import numpy as np`の`as np`は「これ以降この短い名前で呼ぶ」という省略の宣言です。
- `X0, _ = make_moons(...)`の`_`（アンダースコア）は、「この戻り値は使わない」ことを示すPythonの慣習です。`make_moons`は座標とラベルの2つを返しますが、今回はラベルを使いません。
- この時点で`X0`は「2000行×2列」の表です。1行が1つの点、1列目が$x$座標、2列目が$y$座標です。
- `X0.mean(0)`の`0`は「0番目の軸（行方向）に沿って計算する」という指定で、$x$座標の平均と$y$座標の平均が別々に求まります。`std(0)`も同様です。
- `astype(np.float32)`は数値の型を32ビットの小数に変換しています。PyTorchは既定で`float32`を使うので、揃えないと型の不一致でエラーになります。
- `torch.from_numpy`はnumpy配列をPyTorchの`Tensor`（テンソル）に変換します。テンソルは「PyTorchが微分できる多次元配列」だと思ってください。
- `X0[:, 0]`は「全部の行の、0列目」つまり全点の$x$座標です。`scatter`にはこれと$y$座標を渡します。`s=4`は点の大きさです。
- `set_aspect("equal")`は縦横比を1:1に固定します。入れないと月の形が潰れて表示されます。
- `torch.manual_seed(0)`と`np.random.seed(0)`は乱数の種の固定です。拡散モデルは乱数を大量に使うので、指定しないと実行するたびに結果が変わります。`0`という数字自体に意味はありません。
:::

### セル2：forward process

**要点1：`cumprod`が、後半に出てくる総乗$\prod$そのものです。**

```python
alpha_bars = torch.cumprod(alphas, dim=0)   # alpha_bar_t = alpha_1 * ... * alpha_t（数式の総乗Π）
```

cumprodはcumulative product（累積積）で、`[α1, α1α2, α1α2α3, ...]`という列を返します。1ステップごとに元データが$\sqrt{\alpha_t}$倍ずつ薄まるので、$t$ステップ後には$\sqrt{\bar\alpha_t}$倍まで薄まっている、という計算をこの1行で済ませています。

**要点2：関数が`x_t`と`eps`を両方返すことで、教師データが自動的に手に入っています。**

```python
    x_t = torch.sqrt(a_bar) * x0 + torch.sqrt(1 - a_bar) * eps
    return x_t, eps                         # 問題(x_t)と正解(eps)を同時に返すのが要点
```

1行目が、この記事の中心にある式です。元データ`x0`を弱めつつ、その分だけノイズ`eps`を混ぜています。`a_bar`（$\bar\alpha_t$）は1に近いほど元データが強く残っていることを表し、`t`が進むほど小さくなるので、混ぜるノイズの割合が増えていきます。2つの係数の2乗を足すと$\bar\alpha_t + (1-\bar\alpha_t) = 1$になるので、どのステップでも散らばりの大きさが1に保たれる、というのがこの書き方のうまいところです。

そして`return`で返しているのは、ノイズを混ぜた結果`x_t`だけではなく、**混ぜたノイズ`eps`そのもの**です。モデルに当てさせたい正解が`eps`なので、問題と答えを同時に作って返している、という構造になっています。**人間がラベルを用意する作業がどこにもない**のは、この一手のおかげです。

:::details Python / PyTorchの記法メモ（セル2）
- `torch.linspace(1e-4, 0.02, T)`は`0.0001`から`0.02`までを等間隔に1000個並べた列を作ります。`1e-4`は$1\times10^{-4}$です。
- `alphas = 1.0 - betas`は引き算ですが、右辺が1000個の列なので、1000個すべてに対して一度に引き算が行われます。これをブロードキャストといい、PyTorchでは`for`を書かずに配列全体を一括計算するのが基本です。
- 3重引用符の行はdocstringと呼ばれる説明文で、動作には影響しません。
- `alpha_bars[t]`は、`t`が1つの数ではなく「256個のステップ番号が入った列」でも動き、対応する$\bar\alpha_t$を一度に取り出せます。この性質がセル4の学習で効いてきます。
- `.unsqueeze(-1)`は形を整える操作です。`alpha_bars[t]`は「256個」の並びですが、掛ける相手の`x0`は「256行×2列」です。ブロードキャストは末尾の軸から順に形を照合するので、そのままでは`256`と`2`を突き合わせて`The size of tensor a (256) must match the size of tensor b (2)`というエラーになります。`unsqueeze(-1)`で「256行×1列」にすると、長さ1の軸が2列に自動で伸ばされ、各行の$\bar\alpha_t$が$x$座標と$y$座標の両方に正しく掛かります。
- `torch.randn_like(x0)`は「`x0`と同じ形の、標準正規分布に従う乱数」を作ります。
- `alpha_bars[-1]`の`-1`は末尾の要素です。`.item()`はテンソルからPythonの数値を取り出します。

なお、この種の形の不一致は、たまたま`batch_size`と次元数が一致していると**エラーにならず、間違った計算が静かに通ってしまう**ことがあります（`batch_size=2`で2次元データを扱う場合など）。テンソルの形は`print(x.shape)`で確かめる習慣をつけておくと安全です。
:::

### セル3：ノイズを予測する小さなモデル

**要点：入口が`3`、出口が`2`という数字が、このモデルの仕事の定義そのものです。**

```python
            nn.Linear(3, hidden), nn.SiLU(),   # 入力は (x, y, t) の3次元
            nn.Linear(hidden, hidden), nn.SiLU(),
            nn.Linear(hidden, 2),              # 出力は予測したノイズ (2次元)
```

入力3次元は、点の座標$(x, y)$の2つに、今が何ステップ目かという`t`の1つを足したものです。出力2次元は「混ざっていたノイズ」の推定値で、点と同じ次元のベクトルです。つまりこのモデルは「**どこにいて、どれくらいノイズが強い時刻か**」を受け取って「**混ざっていたノイズ**」を答える、それだけの関数です。時刻を教えないと、同じ座標でもノイズの量が違う場合を区別できないので、`t`は必須の入力です。

画像生成で使われる本物の拡散モデル（U-Netなど）も、扱うデータが画像になってネットワークが大きくなるだけで、この入出力の役割は変わりません。

:::details Python / PyTorchの記法メモ（セル3）
- PyTorchでモデルを作るときは`nn.Module`を継承したクラスとして書くのが決まりです。`__init__`は部品を用意する場所、`super().__init__()`はPyTorch側の初期化を呼ぶおまじないで、この2行は毎回同じです。
- `hidden=128`は「指定しなければ128」という既定値の書き方です。
- `nn.Sequential`は「並べた層を上から順に通す」という入れ物です。`nn.Linear(3, hidden)`は3個の数を受け取って128個の数を出す全結合層で、内部に重みとバイアスを持っています。
- `nn.SiLU()`は活性化関数です。線形層だけをいくら重ねても、合成すると1つの線形変換に潰れてしまい、直線的な関係しか表せません。層の間に非線形な関数を挟むことで、月型のような曲がった構造を表現できます。SiLUは$x \cdot \sigma(x)$という形の滑らかな関数で、拡散モデルではよく使われます。
- `forward`はモデルの計算本体で、後で`model(x_t, t)`と書いたときに自動的に呼ばれます（`model.forward(...)`と書かなくてよい）。
- `t.float() / T`でステップ番号を0〜1に正規化しています。`t`は0から999までの整数ですが、そのまま入力すると座標が$-2$〜$2$程度なのに対して桁が違いすぎて、学習がうまく進みません。入力の大きさを揃えるのは基本作法です。
- `torch.cat([x, t_norm], dim=-1)`は座標と時刻を横に連結します。`dim=-1`は「最後の軸（列方向）でつなぐ」で、「256行×2列」と「256行×1列」から「256行×3列」ができます。
- `model.parameters()`は学習対象の重みをすべて集めるメソッド、Adamはその重みをどう更新するかを決めるアルゴリズムです。`lr=1e-3`は学習率で、大きすぎると発散し、小さすぎると学習が進みません。
:::

### セル4：学習する

**要点1：ステップ`t`をランダムに引くことで、1つのネットワークが全てのノイズ強度を担当します。**

```python
    t = torch.randint(0, T, (batch_size,))  # サンプルごとにバラバラなステップを引く（ここが核心）
    x_t, eps = forward_sample(x0, t)      # ノイズを混ぜて、混ぜた正解ノイズepsも受け取る
```

バッチの256個のサンプルに、それぞれ**バラバラな**ステップ番号を割り当てています。`t=0`から`t=999`までを均等にランダムに引くので、モデルは「ノイズが薄い状況」から「ほぼ純粋なノイズの状況」までを、まとめて1つのネットワークで学ぶことになります。ステップごとに別のモデルを用意する必要はありません。

ステップ1から順に999まで辿らなくてよいのは、セル2の式が任意の`t`へ直接ジャンプできる形になっているからです。後半で見るように、これは偏微分方程式の厳密解を使っていることに対応します。

**要点2：やっていることは、生成AIというより素直な回帰問題です。**

```python
    eps_pred = model(x_t, t)              # モデルにノイズを当てさせる
    loss = ((eps_pred - eps) ** 2).mean() # 正解ノイズとの二乗誤差
```

モデルの予測と正解の差を2乗して平均を取る、平均二乗誤差（MSE）です。画像を作る仕組みの中心にあるのが、この2行で書ける「ノイズを当てる練習」だけだというのが、拡散モデルの意外なところです。

:::details Python / PyTorchの記法メモ（セル4）
- ループ1回が1回の重み更新に対応します。`losses = []`は空のリストで、誤差の推移を記録するために使います。
- `X0.shape[0]`はデータの個数（2000）です。`torch.randint(0, 2000, (256,))`で0〜1999の整数を256個ランダムに作り、`X0[idx]`でその番号の点を取り出します。この256個の塊をミニバッチと呼び、毎回違う256個を使うことで学習が安定します。
- `opt.zero_grad()` / `loss.backward()` / `opt.step()`の3行はPyTorchの定型で、順番にも意味があります。`zero_grad()`で前回の勾配を消し、`backward()`で誤差を各重みについて微分（誤差逆伝播）し、`step()`でその勾配に従って重みを更新します。**`zero_grad()`を忘れると勾配が前回の分と足し合わされて学習が壊れる**、という有名な落とし穴があります。
- `losses.append(loss.item())`の`.item()`は、テンソルをPythonの数値に変換しています。テンソルのまま溜め込むと計算グラフごと保持してしまい、メモリを無駄に使います。
:::

### セル5：reverse process

**要点：予測したノイズを引き、揺らぎを少し足し戻す。この2つで逆再生ができています。**

```python
        # 予測したノイズを取り除いた「1ステップ前の平均」
        mean = (1 / torch.sqrt(alpha_t)) * (
            x - (beta_t / torch.sqrt(1 - alpha_bar_t)) * eps_theta
        )
```

学習したモデルが予測した「混ざっていたはずのノイズ`eps_theta`」を、現在の点`x`から引き算する形で取り除いています。係数$\beta_t/\sqrt{1-\bar\alpha_t}$と$1/\sqrt{\alpha_t}$は、後半の数式パートで導く更新式そのままです。出発点は`x = torch.randn(n_samples, 2)`、つまり**データを一切見ていない純粋なガウスノイズ**で、そこから`t=999`から`t=0`まで1000回この操作を繰り返します。

```python
        if t > 0:
            sigma_t = torch.sqrt(beta_t)          # 揺らぎを少しだけ足し戻す
            x = mean + sigma_t * torch.randn_like(x)
        else:
            x = mean                              # 最後のステップは揺らぎを足さない
```

せっかくノイズを取り除いたのに、また少し足し戻しているのが不思議に見えるところです。しかしこれを外すと、生成される点が「一番ありそうな場所」に集まりすぎて、月の形の全体に広がらなくなります。**この揺らぎが、後で出てくるランジュバン方程式のブラウン運動の項に対応しています。** 最後の`t=0`だけ足さないのは、最終出力にわざわざノイズを乗せる理由がないからです。

:::details Python / PyTorchの記法メモ（セル5）
- `@torch.no_grad()`は「この関数の中では勾配を計算しない」という宣言です。生成をするだけなので微分は不要で、外しても結果は同じですが、無駄なメモリと時間を使います。推論時には付けるのが習慣です。
- `reversed(range(T))`で999, 998, ..., 1, 0と逆順に回ります。
- `torch.full((n_samples,), t, dtype=torch.long)`は「全要素が`t`である1000個の列」を作ります。セル4では各サンプルが違う`t`を持っていましたが、ここでは全サンプルが同じ時刻を同時に進みます。`dtype=torch.long`は整数型の指定で、この列を`alpha_bars[t]`のような添字に使うために必要です。
- `frames[t] = x.clone()`の`.clone()`は必須です。`frames[t] = x`と書くと、中身ではなく「同じ場所への参照」が入るため、次のループで`x`が更新された瞬間に保存済みのはずの値も一緒に変わってしまいます。結果として**すべてのコマが最終状態と同じ絵になります**。Pythonで配列を扱うときの典型的な落とし穴です。
:::

### セル7：数値で確かめる

## 直感で理解する「拡散」

コップの水にインクを一滴落とすと、インクは最初は一点に集まっていますが、時間が経つとだんだん水全体に広がって薄くなっていきます。これが物理でいう「拡散」です。拡散モデルのforward processは、まさにこれと同じことをデータに対してやっています。「二つの月」という情報が、ステップを繰り返すごとにノイズという「水」の中に広がって薄まり、最終的には完全に均一な（インクの色が全く分からない）状態になります。

reverse processは、この「広がったインクを一点に集め直す」操作に相当します。物理現象としてはこれは自然には起こりません（インクは自然に広がる一方で、勝手に集まったりはしません）。拡散モデルの本質は、「今この場所にいる点は、集まってほしい方向（＝元データがあった方向）にどれくらい・どちらに動けばよいか」をニューラルネットに学習させることで、この本来ありえない逆再生を人工的に作り出している点にあります。

## 数式で理解する

ここから数式が出てきますが、使う記号は次の表に尽きます。すべてこれまでのコードに出てきた変数と1対1で対応しているので、迷ったらこの表に戻ってきてください。

### forward process：マルコフ連鎖として書く

先ほどのコードのforward processは、数式で書くとこうなります。

$$
x_t = \sqrt{\bar\alpha_t}\, x_0 + \sqrt{1 - \bar\alpha_t}\, \epsilon, \qquad \epsilon \sim \mathcal{N}(0, I)
$$

$\epsilon \sim \mathcal{N}(0, I)$は「$\epsilon$は平均0・分散1のガウス分布から引いてくる」と読みます。これを1ステップずつの条件付き分布として書き直すと、

$$
q(x_t \mid x_{t-1}) = \mathcal{N}\!\left(\sqrt{1-\beta_t}\, x_{t-1},\ \beta_t I\right)
$$

となります。左辺は「$x_{t-1}$が与えられたときの$x_t$の分布」という意味で、右辺は「$x_{t-1}$を$\sqrt{1-\beta_t}$倍したところを中心に、分散$\beta_t$だけばらつく」と読みます。

この形は**マルコフ連鎖**と呼ばれます。難しそうな名前ですが、意味は「次の状態が、**直前の状態だけ**で決まる」という一点に尽きます。$x_t$を決めるのに必要なのは$x_{t-1}$だけで、$x_{t-2}$やそれ以前にどう動いてきたかという履歴は一切使いません。コードでも`forward_sample`は`x0`と`t`しか受け取らず、途中経路を覚えていないことが確認できます。すごろくで次のマス目が今いるマスとサイコロだけで決まるのと同じで、物理でいう「記憶を持たない過程」です。

@[card](https://ja.wikipedia.org/wiki/%E3%83%9E%E3%83%AB%E3%82%B3%E3%83%95%E9%80%A3%E9%8E%96)

上の2つの式をつなぐのが、$\alpha_t$と$\bar\alpha_t$の関係です。

$$
\alpha_t = 1 - \beta_t, \qquad \bar\alpha_t = \prod_{s \le t}\alpha_s = \alpha_1 \alpha_2 \cdots \alpha_t
$$

ここで$\prod$（大文字のパイ）は**総乗**の記号です。和を表す$\sum$（シグマ）の掛け算版で、$\prod_{s \le t}\alpha_s$は「$s$を1から$t$まで動かして、$\alpha_s$を全部かけ合わせる」という意味です。階乗$t! = 1 \times 2 \times \cdots \times t$を、かける中身が$\alpha_s$に変わったものだと思えば十分です。1ステップごとに元データが$\sqrt{\alpha_t}$倍ずつ薄まっていくので、$t$ステップ後には$\sqrt{\alpha_1}\sqrt{\alpha_2}\cdots\sqrt{\alpha_t} = \sqrt{\bar\alpha_t}$倍まで薄まっている、という計算になります。コードの`alpha_bars = torch.cumprod(alphas, dim=0)`（cumulative product、累積積）がちょうどこの$\prod$を計算している部分です。

各$\alpha_s$は1より少し小さい数なので、これをたくさんかけ合わせると指数関数的に小さくなります。実際$\log(1-\beta) \simeq -\beta$を使えば

$$
\bar\alpha_t = \prod_{s \le t}(1 - \beta_s) \simeq \exp\left(-\sum_{s \le t}\beta_s\right)
$$

となり、セル2で$\bar\alpha_{T-1} \approx 4 \times 10^{-5}$という小さな値が出てきたのは、$\beta_s$の総和が約10になっていて$e^{-10}$程度になるためだと分かります。「$T$と`betas`はセットで決める」というのは、この総和$\sum\beta_s$を十分大きくしなければならない、という意味だったわけです。

### 連続極限：確率微分方程式とItôの補題

ステップを細かく・無限に取っていく極限を考えると、この離散的なマルコフ連鎖は確率微分方程式（SDE）に移ります。$\beta_t = \beta(t)\Delta t$と書いて$\Delta t \to 0$とすると、$\sqrt{1 - \beta(t)\Delta t} \simeq 1 - \frac{1}{2}\beta(t)\Delta t$なので、1ステップの変化は

$$
x_t - x_{t-1} \simeq -\frac{1}{2}\beta(t)\, x_{t-1} \Delta t + \sqrt{\beta(t)\Delta t}\,\epsilon
$$

となります。$\sqrt{\Delta t}\,\epsilon$をウィーナー過程（ブラウン運動）の増分$dW$と書けば、これは

$$
dx = -\frac{1}{2}\beta(t)\, x\, dt + \sqrt{\beta(t)}\, dW
$$

の離散化（Euler-Maruyama法）そのものです。物理でいえば、バネで原点に引き戻されながら熱的に揺らされている粒子の運動方程式（オルンシュタイン・ウーレンベック過程）です。

ここで見落としてはいけないのが、**ノイズ項が$\Delta t$ではなく$\sqrt{\Delta t}$のオーダーである**ことです。$dW \sim \sqrt{dt}$なので$(dW)^2 \sim dt$となり、通常の微積分なら「2次だから無視できる」項が、確率微分方程式では1次の項として生き残ります。これがあるために、$x$の関数$f(x)$の微分に普通の連鎖律$df = f'(x)\,dx$を使うことができません。正しくは2次の項まで残した**Itôの補題**

$$
df(x) = f'(x)\, dx + \frac{1}{2}f''(x)\, (dx)^2, \qquad (dx)^2 = \beta(t)\, dt
$$

を使う必要があります。この第2項が、次に出てくるFokker-Planck方程式の拡散項を生み出します。連鎖律だけで済ませると移流項しか出てこないので、ここは形式的な細部ではなく本質的な部分です。

以上を使うと、確率密度$p(x,t)$の時間変化はFokker-Planck方程式

$$
\frac{\partial p}{\partial t} = \frac{1}{2}\frac{\partial}{\partial x}\left[\beta(t)\, x\, p\right] + \frac{1}{2}\beta(t)\frac{\partial^2 p}{\partial x^2}
$$

に従います。

:::details Itôの補題からFokker-Planck方程式を導く
一般の確率微分方程式$dx = a(x,t)\,dt + g(t)\,dW$を考えます。任意の滑らかなテスト関数$f(x)$にItôの補題を当てはめて期待値を取ると、$\mathbb{E}[dW] = 0$、$(dW)^2 = dt$より

$$
\frac{d}{dt}\mathbb{E}[f(x)] = \mathbb{E}\!\left[f'(x)\, a + \frac{1}{2}f''(x)\, g^2\right]
$$

を得ます。左辺を$\frac{d}{dt}\int f(x)\, p(x,t)\, dx = \int f(x)\, \frac{\partial p}{\partial t}\, dx$と書き、右辺も$p$による積分で書けば

$$
\int f\, \frac{\partial p}{\partial t}\, dx = \int \left(f' a + \frac{1}{2}f'' g^2\right) p\, dx
$$

となります。右辺を部分積分して$f$の微分を$p$側に移します（$|x| \to \infty$で$p$とその微分が十分速く0になるとして境界項を落とします）。第1項は1回、第2項は2回の部分積分で

$$
\int f\, \frac{\partial p}{\partial t}\, dx = \int f \left(-\frac{\partial}{\partial x}(a p) + \frac{1}{2}\frac{\partial^2}{\partial x^2}(g^2 p)\right) dx
$$

となり、$f$が任意なので被積分関数を等置できて

$$
\frac{\partial p}{\partial t} = -\frac{\partial}{\partial x}\left[a(x,t)\, p\right] + \frac{1}{2}\frac{\partial^2}{\partial x^2}\left[g(t)^2\, p\right]
$$

が得られます。ここに$a = -\frac{1}{2}\beta(t)x$、$g^2 = \beta(t)$を代入すれば本文の式になります。第2項がItôの2次項$\frac{1}{2}f''g^2$から来ていることに注意してください。連鎖律のみで$df = f'dx$としてしまうと第1項の移流項しか現れず、拡散項が完全に落ちてしまいます。
:::

右辺第2項は、物理でおなじみの拡散方程式（熱方程式）$\partial p/\partial t = D\, \partial^2 p/\partial x^2$と、拡散係数を$D = \beta(t)/2$と読み替えれば同じ形をしています。つまりforward processは、名前の通り本当に「拡散」の物理そのものだということです。右辺第1項は、原点に向かって引き戻す力に対応する移流項で、これがあるおかげでデータは無限に広がっていかず、分散1のガウス分布に落ち着きます。

面白いことに、この方程式の解はセル2のコードそのものです。$\bar\alpha(t) = \exp\left(-\int_0^t \beta(s)\, ds\right)$とおくと、

$$
p(x,t) = \mathcal{N}\!\left(\sqrt{\bar\alpha(t)}\, x_0,\ 1 - \bar\alpha(t)\right)
$$

がFokker-Planck方程式を厳密に満たします（代入すれば確認できます）。つまり`forward_sample`のたった1行は、偏微分方程式を数値的に解いた近似ではなく、その厳密解を直接サンプリングしているのです。だからこそ、途中のステップを1つずつ辿らずに、好きな$t$へ一足飛びにジャンプできます。学習ループで`t = torch.randint(0, T, ...)`とランダムな$t$を直接指定できたのは、この性質のおかげです。

### reverse process：スコア関数とランジュバン方程式

セル5のノイズ除去の式は、実は「スコア関数」と呼ばれる量

$$
s(x_t, t) := \nabla_x \log p_t(x_t) \approx -\frac{\epsilon_\theta(x_t, t)}{\sqrt{1-\bar\alpha_t}}
$$

を使って書き直すことができます。記号を確認しておくと、$\nabla_x$は$x$についての勾配（各成分で偏微分してベクトルに並べたもの）、$\log p_t$は確率密度の対数、$:=$は「左辺を右辺で定義する」という意味です。したがって$s$は「その場所から見て、確率密度が最も急に増える向きと大きさ」を表すベクトルです。標高地図の上で最も急な上り坂の向きを指す矢印、と思えばよく、密度の山（＝データが多い場所）を指す矢印になります。

$\epsilon_\theta$に$-1/\sqrt{1-\bar\alpha_t}$を掛けたものがスコアだ、というこの対応が、「ノイズを当てる回帰問題」と「確率分布の勾配を学ぶこと」を結びつけている要点です。式の形も納得しやすくて、$x_t = \sqrt{\bar\alpha_t}x_0 + \sqrt{1-\bar\alpha_t}\epsilon$を$\epsilon$について解くと$\epsilon = (x_t - \sqrt{\bar\alpha_t}x_0)/\sqrt{1-\bar\alpha_t}$であり、一方でガウス分布$\mathcal{N}(\sqrt{\bar\alpha_t}x_0, 1-\bar\alpha_t)$の対数を$x_t$で微分すれば$-(x_t - \sqrt{\bar\alpha_t}x_0)/(1-\bar\alpha_t)$になります。両者を見比べれば、ちょうど$-1/\sqrt{1-\bar\alpha_t}$倍の関係になっていることが読み取れます。この$s$を使ってセル5の更新式を書き直し、$\beta_t \ll 1$として$1/\sqrt{1-\beta_t} \simeq 1 + \beta_t/2$と展開すると、$\beta_t$の1次までの精度で

$$
x_{t-1} \simeq x_t + \frac{\beta_t}{2}\Big(x_t + 2\, s(x_t, t)\Big) + \sqrt{\beta_t}\, z, \qquad z \sim \mathcal{N}(0, I)
$$

となります。これは物理のランジュバン方程式（ブラウン運動する粒子に、ある力が加わったときの運動方程式）

$$
dx = -\nabla U(x)\, dt + \sqrt{2D}\, dW
$$

と同じ構造をしています。ここで$U(x)$はポテンシャル（位置エネルギー）、$-\nabla U$はそこから決まる力、$D$は拡散係数、$dW$は先ほどと同じブラウン運動の増分です。右辺第1項の$-\nabla U$が「データらしい方向に引く力」、第2項の$\sqrt{2D}\,dW$がランダムな揺らぎで、コードでは前者が`eps_theta`から作られる`mean`、後者が`sigma_t * torch.randn_like(x)`に対応します。スコア関数$s(x,t)$は、$U = -\log p_t$というポテンシャルを考えたときの力$-\nabla U$そのものであり、確率密度が高い方向（＝データらしい方向）を指しています。

なお$s$に係数2が付いているのと、括弧の中に$x_t$が残っているのは、単に分布$p_t$の上をランダムに歩き回る（ランジュバン・サンプリング）のではなく、forward processが原点に引き戻した分をきちんと打ち消しながら時間を遡る必要があるためです。ここが、拡散モデルの逆過程が「ただのブラウン運動」ではない部分です。

## 統計力学とのつながり

先ほど、forward processが物理のオルンシュタイン・ウーレンベック過程と同じものだと述べました。これはバネのような復元力（調和振動子ポテンシャル$U(x) = x^2/2$）の中でブラウン運動する粒子と数学的に同じです。統計力学では、このような系は十分時間が経つと、ボルツマン分布

$$
p_{\text{eq}}(x) \propto \exp\left(-\frac{U(x)}{k_B\mathcal{T}}\right)
$$

に落ち着くことが知られています。$p_{\text{eq}}$は平衡状態（equilibrium）での確率密度、$k_B$はボルツマン定数、$\mathcal{T}$は温度です。$\propto$は「比例する」という意味で、全体を積分して1になるように規格化する定数は省略してあります。

:::message
ここでの温度を$\mathcal{T}$と書いたのは、拡散モデルの総ステップ数$T$と紛らわしいためです。物理の教科書では両方とも$T$と書かれるので、混同しないよう注意してください。
:::

$U(x) = x^2/2$を代入すると$p_{\text{eq}}(x) \propto \exp\left(-x^2/(2k_B\mathcal{T})\right)$、つまり分散$k_B\mathcal{T}$のガウス分布になります。さらに拡散モデルで使われるノイズの強さは、ちょうど$k_B\mathcal{T} = 1$に相当する大きさに選ばれていて、平衡状態が標準正規分布$\mathcal{N}(0, 1)$になるように設計されています。まさにセル2で確かめた「$t = T-1$で$\sqrt{\bar\alpha}$が0.006まで落ちて、完全なガウスノイズになる」という結果と一致しています。つまり拡散モデルの「最終状態がガウス分布になる」という設計は、思いつきではなく、統計力学的な平衡状態そのものを利用しているということです。

そしてこの見方に立つと、セル2で見た`T`と`betas`の関係も自然に理解できます。$\bar\alpha_{T-1}$が十分に0まで落ちていないというのは、物理の言葉でいえば「まだ平衡状態に達していない」ということです。平衡に達する前に打ち切ってしまうと、reverse processが出発点として仮定している$\mathcal{N}(0, I)$と、forward processが実際にたどり着いた分布がずれてしまいます。

reverse processが行っているのは、この平衡状態（ノイズ）から出発して、統計力学的には「ありえない」非平衡状態（データ）へ時間を遡る操作です。それを可能にしているのが、モデルが学習した「今の位置でどちらに力がかかっているか」というスコア関数（＝ポテンシャルの勾配にマイナスをつけた向き、すなわち力の推定）なのです。

## まとめと次のステップ

2次元のトイデータを使うことで、拡散モデルが「データを少しずつノイズに埋める（forward）」「学習したスコア関数を使ってノイズから引き上げる（reverse）」という2つの操作の組み合わせでできていることを、実際に動くコードで確認できました。そしてこの仕組みは、インクの拡散やブラウン運動といった物理現象と、数式のレベルでそのまま対応しています。
