# Zenn人気記事の実測解析（2026-08-08 実施）

`scripts/zenn_analyze.py` で Zenn 公開API から 2,620 記事を収集して解析した記録。
CLAUDE.md / write-article スキルの改定根拠はここに置く。再測するときは同じスクリプトを使う。

## 測り方（ここを間違えると誤った結論が出る）

生存者バイアスを避けるため、2群を作って**判別的に**比較した。

- **WIN** … 100いいね以上（実際に伸びた記事）
- **BASE** … 公開から30日以上経過 かつ 10いいね未満（伸びなかったことが確定した記事）
- 公開直後で0いいねの新着は「失敗」ではないので BASE から除外する
- Zennの読者層・競争環境が近い **2024年以降**に限定

2024年以降 2,017件 → WIN 463件 / BASE 290件。
以下の「WIN率」は WIN/(WIN+BASE) で、この母集団の平均は **61.5%**。
61.5%より高ければ有利、低ければ不利、という読み方をする。

## 1. タイトル

### 最重要: 「：」で副題を足す構造は個人アカウントでは致命的

| 条件 | WIN率 |
|---|---|
| 「：」あり | 28.1% |
| 「：」なし | **64.6%** |

交絡を潰しても一貫して残った。

| 層別 | 「：」あり | 「：」なし |
|---|---|---|
| 個人アカウント（我々はこれ） | **17.3%** | 55.0% |
| 企業Publication | 75.0% | 85.6% |
| 機械学習系ジャンル内 | 5.3% | 9.9% |
| タイトル20-35字に固定 | **13.6%** | 70.1% |
| タイトル35-50字に固定 | 32.1% | 66.1% |

「：」ありで勝っている記事は、**コロンの手前がすでに集客力を持っている**場合に限られる
（例:「Claudeトークン消費を抑えて５倍使う: 「原始人」口調が80%削減」）。
「拡散モデルをMNISTで動かす：…」のように手前が引きにならない場合、副題は効かない。

企業Publicationは「：」があっても勝つ（配信力が別にあるため）。
企業ブログの書き方を個人が真似すると負ける、というのが実測の結論。

| 特徴 | WIN% | BASE% | 差 |
|---|---|---|---|
| 具体的なツール/製品名を含む | 54.6% | 16.9% | **+37.7pt** |
| 口語・感情の語彙 | 15.1% | 6.6% | +8.6pt |
| 一人称（私/僕/自分）が出る | 3.9% | 1.4% | +2.5pt |
| 疑問形（?/か） | 9.9% | 6.2% | +3.7pt |
| 完全/決定版/まとめ | 7.3% | 2.8% | +4.6pt |

| 数字を含む | 22.5% | 33.1% | -10.6pt |

| 語り口 | n | WIN率 |
|---|---|---|
| 口語のみ | 87 | **78.2%** |
| どちらでもない | 617 | 59.0% |

### 長さ

WIN中央値 **31字**、BASE中央値 35字。50字を超えると不利（WIN 10.2% / BASE 18.6%）。
**20〜30字**が最も勝ち側に偏る（WIN 31.1% / BASE 22.8%）。

## 2. 本文の量

| 本文の文字数 | WIN% | BASE% |
|---|---|---|
| 〜3,000字 | 8.6% | **27.9%** |
| 3,000-6,000字 | 29.2% | 31.0% |
| 6,000-10,000字 | 24.4% | 21.4% |
| 10,000-20,000字 | **26.6%** | 13.4% |
| 20,000字〜 | 11.2% | 6.2% |

中央値は WIN 7,662字 / BASE 5,032字。AI原理解説ジャンルに限ると WIN 8,361字 / BASE 5,343字。
**3,000字未満はほぼ読まれない**。1万字前後が最も勝ち側に偏る。

## 3. 構成

| 指標 | WIN | BASE |
|---|---|---|
| h2の数 | 7 | 5 |
| h3の数 | **5** | 2 |

見出しの書き方（AI原理解説ジャンル内、WIN 141 / BASE 258）:

| 見出しの型 | WIN% | BASE% | 差 |
|---|---|---|---|
| 疑問形の見出しがある | 25.5% | 12.4% | **+13.1pt** |
| 「そもそも/なぜ」で始まる見出し | 14.9% | 10.1% | +4.8pt |
| 口語の見出し | 13.5% | 7.4% | +6.1pt |
| 手順ラベル見出し（セルN/手順N/StepN） | 2.1% | 1.9% | ±0 |

**手順ラベルの見出しは、勝っている記事ではほとんど使われていない（2.1%）。**
Zennはサイドバーに目次が出るので、目次が「セル1／セル2／セル3」だと
読む理由が1つも提示されないまま終わる。

> そもそも尤度って何？ / 生成AIは本当に確率分布を学習しているのか？ /

### 読み方

- `ai` は天井が最も高いが、新着48件が**0日**（同じ日に48本投稿される）。
  新着経由の露出は数時間で消える。
- 現行CLAUDE.mdの「転換枠」の主張は**実測で裏付けられた**。
  `huggingface` 19.0%、`物理` 13.1%、`diffusion` 11.9% は10いいね到達率が全トピック中で最も高い。
  新着に何ヶ月も居座れる（物理240日、diffusion1348日）ことが効いている。
- ただし `物理` は**歴代1位が38いいね**。このトピックだけでは天井が38。
  転換枠は「読んだ人が反応する枠」として維持する価値はあるが、
  流入をここに頼ってはいけない。
- `machinelearning` は天井1,032と高いが、30日後に10いいね到達率3.1%・
  0いいね率50.8%。母数は大きいが競争が激しく、通過率は低い。
- **`deeplearning` が唯一「天井」と「通過率」を両立している。**
  天井1,032（machinelearningと同じ）でありながら、回転29日・転換率15.3%・いいね0率24.8%。
  machinelearningと同じ天井を持ちながら、通過率は6倍。優先して使う。

## 5. 我々の記事の診断

| いいね | 字数 | コード | 図 | 疑問形見出し | タイトル |
|---|---|---|---|---|---|
| 1 | 26,462 | 21 | 1 | 0 | 拡散モデルの中身を覗いてみる**：**物理の「拡散」から生成AIを理解する |
| 1 | 4,328 | 6 | 2 | 0 | Hugging Face推論APIで動かすtext-to-image**：**FLUX.1-schnellをColabのセル3つで（61字） |
| 1 | 6,112 | 9 | 1 | 1 | Colabのセル3つで作るLLMチャットボット**：**Hugging Face推論APIの最小構成（46字） |
| 0 | 15,525 | 18 | 2 | 0 | LLMのtemperatureは本当に温度だった。最新のClaudeからは消えていたけれど（45字） |
| 0 | 18,070 | 13 | 3 | 0 | 拡散モデルをMNISTで動かす**：**トイモデルから本物のU-Netへ |

不利な条件が重なっている:

1. 5本中4本が「：」副題構造（個人アカウントのWIN率17.3%の型）
2. タイトルが45〜61字（不利帯）
3. 見出しが「セル1／セル2／…」の手順ラベル（勝者の2.1%しか使わない型）
4. 図が1〜3枚（このジャンルの勝者は10〜20枚）
5. コードが6〜21個で、図より多い（勝者は逆）
6. Colab記事2本が4,328字・6,112字（3,000-6,000字帯は最も不利）
7. topicsに `物理`(天井38)・`diffusion`(天井110)・`huggingface`(天井106) を採用しており、
   流入枠が実質的に機能していない

**重要**: 内容の質の問題ではなく、**流通の型**の問題として切り分けられる。
対照群（伸びなかった記事）には「Diffusion LM入門（解説編）：逐次生成を脱却し…」
「Just Train Twice 論文解説：…」「C = 1/f：モード間エネルギー輸送に関する導出」など、
我々と同じ書き方の真面目な長文が並んでいる。この型は読まれない。
